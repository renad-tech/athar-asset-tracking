# أثَر | ATHAR

نظام رقمي لتوثيق تسليم واستلام وعُهد الأصول والمرافق الجامعية. يستبدل أثر النماذج الورقية غير الموثوقة بتحقق من الهوية عبر QR وطبقة رؤية حاسوبية تعمل على الجهاز نفسه، توثّق حالة الأصل وتقارنها عبر الوقت — عشان يطلع الطرفين بسجل موثّق وقابل للمقارنة، مو بس ذاكرة أو ورقة موقّعة.

بُني لهاكاثون الجامعة الذكية.

**English:** الوصف بالإنجليزي متوفر في [README.md](README.md).

## ليه أثر؟

- **طرفين موثّقين، مو مفتش واحد.** كل جلسة تسليم أو عهدة تحتاج المُسلِّم والمستلم يكونوا محددين ويوقعوا — مو شخص واحد يوثق ملاحظته الشخصية.
- **هوية من قاعدة بيانات حقيقية، مو نص حر.** الطرفين يتحددوا بمسح بطاقة QR مرتبطة بسجل موظف فعلي، مو كتابة اسم يدوياً.
- **سجل حالة لكل أصل، مو مجلد صور متفرقة.** كل جلسة تُحفظ داخل سلسلة عهدة ذلك الأصل بالذات، فأي حد يقدر يفتح الأصل لاحقاً ويشوف كل الجلسات اللي مرت عليه مرتبة بالوقت.
- **كشف تغيّر فعلي، مو مقارنة يدوية للصور.** صورة مرجعية تُقارن مع الإطار الحي من الكاميرا بتحليل فرق الإضاءة على مستوى البكسل، عشان يفرّق بين تحريك فعلي وحركة عابرة (تفاصيل أكثر في قسم [الرؤية الحاسوبية](#الرؤية-الحاسوبية)).

## المزايا

- **تسجيل دخول آمن للمشرف** بالرقم الوظيفي، يتحقق من جدول `supervisors` فعلياً.
- **نوعين من الجلسات:**
  - **العهدة** — صرف عهدة جديدة أو مراجعة سلسلة عهدة موجودة لأصل ماسكه موظف لفترة طويلة.
  - **التسليم والاستلام** — نقل مسؤولية أصل بين طرفين في لحظة واحدة.
- **تحديد هوية الطرفين عبر QR** (المُسلِّم والمستلم)، مسح مباشر من الكاميرا، مع إدخال يدوي كبديل.
- **توثيق حالة كل صنف** — صورة، وسم حالة (سليم / تالف / يحتاج صيانة)، وملاحظة نصية لكل عنصر داخل الجلسة.
- **نص إقرار قانوني يتولّد تلقائياً** يذكر الطرفين والأصل والتاريخ، مع تاريخ إعادة فحص يحدده المستلم، ويُختم بتوقيع رقمي.
- **محضر رقمي فوري** — الموقع، المُسلِّم، الرقم الوظيفي، الرقم التسلسلي، صورة الحالة، الملاحظات، والتوقيع، مرتبط دائماً بنفس الأصل.
- **عرض سلسلة العهدة** — كامل التاريخ الزمني لكل الجلسات المرتبطة بأصل واحد.
- **توليد بطاقات QR للموظفين**، قابلة للتصدير كملف PDF جاهز للطباعة.
- **يعمل بدون إنترنت (Offline-first)** — الجلسات تُحفظ محلياً، والتطبيق يشتغل بدون اتصال، وتتم المزامنة تلقائياً عند رجوع الاتصال.
- **قاعدة بيانات Supabase** لحفظ الموظفين، المشرفين، الجلسات، وسجلات العهد.

## الرؤية الحاسوبية

يحتوي أثر على طبقتين مستقلتين للرؤية الحاسوبية (انظر [`src/vision.ts`](src/vision.ts)):

1. **المحرك الأساسي (جافاسكريبت خام، يعمل Offline من أول ثانية، بدون أي تحميل)**
   - مسح بطاقات QR
   - صورة مرجعية لحالة المشهد "الطبيعية"
   - كشف الحركة بين الإطارات المتتالية
   - كشف التحريك الفعلي — مقارنة الإطار الحي بالمرجعي لرصد غرض تم تحريكه أو أصبح مفقوداً فعلياً، بشكل مختلف عن مجرد مرور شخص أمام الكاميرا
2. **كاشف اختياري للأشخاص/الأجسام (TensorFlow.js + COCO-SSD)** — يتعرّف على الأشخاص والأغراض الشائعة (حاسوب محمول، هاتف، كرسي...) بالاسم. يُفعَّل فقط بعد تحميل النموذج محلياً (التفاصيل تحت)؛ وكل ما سبق يستمر بالعمل بدونه.

## طريقة التشغيل

### المتطلبات
- Node.js 22+ و pnpm (انظر `.mise.toml`)
- مشروع [Supabase](https://supabase.com)

### ١) تثبيت الحزم
```bash
npm install
```

### ٢) إعداد قاعدة البيانات
افتح مشروع Supabase ← SQL Editor ← الصق كامل محتوى `supabase_schema.sql` ← Run.
هذا ينشئ جداول `employees`، `supervisors`، وجداول الجلسات والعهد. الملف آمن للتشغيل أكثر من مرة.

### ٣) إعداد متغيرات البيئة
```bash
cp .env.example .env
```
املأ ملف `.env` برابط ومفتاح مشروع Supabase (من Supabase ← Project Settings ← API). متغير `VITE_AI_API_KEY` اختياري — اتركه فارغاً لإبقاء كشف الذكاء الاصطناعي محاكى.

### ٤) (اختياري) تحميل نموذج كشف الأجسام
```bash
npm run download-model
```
يُفعّل طبقة التعرف على الأشخاص/الأجسام (COCO-SSD). التطبيق يعمل بالكامل بدون هذه الخطوة، بالاعتماد على كشف الحركة و QR فقط.

### ٥) تشغيل سيرفر التطوير
```bash
npm run dev
```
افتح **http://localhost:8443** — المنفذ ثابت في `vite.config.ts`.

> الكاميرا تحتاج سياقاً آمناً: `localhost` أو `https://` فقط. لن تعمل عبر `file://` أو عنوان شبكة محلي مثل `http://192.168.x.x`.

### ٦) البناء للإنتاج
```bash
npm run build
```

## طريقة استخدام الموقع

١. **سجّل الدخول** بالرقم الوظيفي.
٢. **اختر نوع الجلسة** — عهدة أو تسليم واستلام.
٣. **حدّد الأطراف** بمسح بطاقتي QR الخاصة بالمُسلِّم والمستلم.
٤. **وثّق حالة كل صنف** — صورة، وسم حالة، وملاحظة إن لزم.
٥. **راجع ووقّع الإقرار** — النص القانوني يتولّد تلقائياً، حدّد تاريخ إعادة الفحص ووقّع رقمياً.
٦. **احصل على المحضر الرقمي** — يتولّد فوراً ويُحفظ في سلسلة عهدة الأصل للرجوع له لاحقاً.

## هيكل المشروع

```
src/
  App.tsx              # هيكل التطبيق والتنقل
  ScreenHome.tsx        # اختيار نوع الجلسة
  ScreenHandover.tsx    # مسار التسليم والاستلام (الأطراف ← التصوير ← الإقرار)
  ScreenCustody.tsx     # مسار العهدة
  ScreenChain.tsx       # عرض سلسلة العهدة / التاريخ
  ScreenReport.tsx       # المحضر الرقمي
  Badges.tsx            # توليد بطاقات QR
  BadgeScanner.tsx      # مسح QR
  vision.ts             # محرك الرؤية الحاسوبية (حركة، تحريك، COCO-SSD)
  services/
    api.ts               # طبقة البيانات المرتبطة بـ Supabase
    custody.ts
supabase_schema.sql     # هيكل قاعدة البيانات
```
